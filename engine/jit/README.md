# engine/jit

The JIT to WebAssembly ([docs/jit.md](../../docs/jit.md)): compiles hot JSC bytecode into WASM
functions at run time. Built into JavaScriptCore of the engine and of the `jsc` shell through
`jit.cmake`, which `Source/JavaScriptCore/CMakeLists.txt` includes (patch 0067); the C loop calls
it through `LLIntWasmJIT.h`. On unless `BL_JIT=0`.

fast paths for hashing code against their int32 twins), `tests/jsc/jit-recompile.js` (compiled code
through a full GC, and code thrown away compiles again), `tests/jsc/jit-tierup.js` (a loop entered
once gets V8's optimized code), `tests/jsc/jit-calls.js` (many callees at one site cost about
as much as one), `tests/jsc/jit-keyed.js` (many keys and shapes at one site cost about an array element's
access), `tests/jsc/jit-size.js` (the module of a large VM-like function stays at most 12 times its bytecode, and `if (s) t = u` and `s = s ^ c` at most 130 and 115 bytes of WASM per statement; run.sh reads the sizes in the JIT's log), `tests/jsc/jit-branch-hints.mjs` (the branch hints of that module's largest function: before the code section, in order, each on an `if` or `br_if`, at least one per 100 bytes of code; run.sh writes the modules with `BL_JIT=3`), `tests/jsc/jit-warmup-map.js` (calls with 8000 warm functions cost about as much as with 500), `tests/jsc/jit-literals.js` (array literals of every indexing type and getters against the interpreter's results, while profiles, shapes, getters and prototypes change, also with the GC collecting continuously), `tests/jsc/jit-literal-speed.js` (an array literal against element writes, a getter against a method call), `tests/jsc/jit-scope.js` (globals and closure variables against local variables, also writes of closure variables), `tests/jsc/jit-intrinsics.js` (`Math.imul`, `charCodeAt` and the DataView getters at sites that read them by name, and typed array elements of the one type a site saw, against the host functions and the interpreter, also with other callees, `this` values, types, detached and resizable buffers and replaced host functions), `tests/jsc/jit-intrinsic-speed.js` (a Uint8Array's elements, a DataView getter and `charCodeAt` against an int32 array's inline elements), `tests/jsc/jit-elements.js` (element reads and writes against the same arithmetic without them), `tests/jsc/llint-two-shapes.js` (a `get_by_id` that sees two shapes takes the second structure of the interpreter's cache, patch 0179), `tests/jsc/jit-megamorphic.js` (reads by name at sites of many shapes against `Reflect.get`, also while prototypes, getters and properties change, and about as fast as at a site of one shape), `tests/jsc/strict-equality.js` (`===` and `!==` of every kind of value against a reference without them, interpreted and compiled) and `tests/jsc/strict-equality-speed.js` (two tags and atoms against int32, patch 0185), `tests/engine/gc-test.mjs` (the GC inside a generic call of compiled code and inside a bound
function's call of its target), `tests/engine/jit-warmup-test.mjs` (code that ran briefly stays
interpreted, a large function warms up longer than a small one, hot code compiles, and so does a
large function whose loop runs long iterations, by its time in the interpreter), `tests/engine/pages/tail-calls.html` (no frame of a tail call in stack walks after tier-up: postMessage's source through `call`, `apply`, `Reflect.apply` and bound functions of another frame, `Error.stack`, results of tail calls, also of a host function with more arguments than its caller had and of a function with more arguments that calls a host function).
